# Bruno: B2 аккаунты и личные данные

26 последовательных запросов покрывают все 11 операций B2: register/login/logout, GET/PATCH профиля, GET/PUT/DELETE сохранённых и личных отметок заявки. Дополнительно проверяются повторные PUT, неизменный `markedAt`, независимость списков, два аккаунта и 401 после logout.

Рекомендуемый запуск — [изолированный B2 runner](../../scripts/b2/README.md). Он создаёт временную БД/DEMO-сервер, случайные пароли и два синтетических аккаунта, запускает коллекцию, затем удаляет среду. У CLI **4.2.1** общий lockfile в `tools/bruno`; в этой папке нет второго npm-дерева.

`environments/local.bru` содержит только `baseUrl`. Тела register/login читают `HACKATLAS_B2_EMAIL_A`, `HACKATLAS_B2_EMAIL_B` и `HACKATLAS_B2_PASSWORD` через `process.env`; их передаёт runner. Токены хранятся через `bru.setVar` в памяти процесса, не записываются в environment-файл и отзываются в конце последовательности. Пароль нельзя задавать в CLI-аргументе или добавлять в Git.

Для просмотра в Bruno GUI можно открыть папку коллекции и выбрать `local`. Ручной запуск создаёт аккаунты на указанном сервере, поэтому используйте отдельную тестовую БД и одноразовые данные. GUI сохраняет историю ответов по своим настройкам; для автоматической проверки с удаляемой средой используйте runner. Здесь нет B3 moderation/delete-account, JWT или refresh endpoint.

Последовательность рассчитана на канонический DEMO ID AI Sprint, явно включённый dev signup и пустые личные списки новых аккаунтов. Отметка `APPLIED` всегда `selfReported=true`: тест не имитирует подтверждение организатора.
