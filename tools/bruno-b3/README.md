# Bruno: B3 модерация и удаление аккаунта

Коллекция содержит **24 последовательных запроса**. Она создаёт два одноразовых аккаунта и вторую сессию первого, отправляет предложение события и report, проверяет `202 PENDING`, ошибки доступа/валидации и удаление аккаунта. После удаления обе сессии первого аккаунта должны получить `401`; второй аккаунт и его закладка остаются доступными. В конце удаляется и второй тестовый аккаунт.

**Запускайте через [изолированный B3 runner](../../scripts/b3/README.md)**: он создаёт отдельный PostgreSQL/DEMO-сервер и одноразовые учётные данные. Эти запросы действительно удаляют созданные аккаунты; коллекция не предназначена для проверки на личном аккаунте или общей dev-БД.

Bruno CLI **4.2.1** и lockfile остаются общими в `tools/bruno`. В этой папке нет второго npm-дерева. `environments/local.bru` содержит только `baseUrl`. Runner передаёт `HACKATLAS_B3_EMAIL_A`, `HACKATLAS_B3_EMAIL_B`, `HACKATLAS_B3_PASSWORD` через environment дочернего процесса. Токены сохраняются только как runtime variables `bru.setVar`; не добавляйте их в файлы коллекции или CLI-аргументы.

В GUI можно открыть коллекцию для изучения HTTP-последовательности при подключении мобильных форм M3. Запуск в GUI использует его настройки сервера и историю; безопасная воспроизводимая проверка с удаляемой средой выполняется runner. Все запросы отключают redirects. Удаление аккаунта требует явного password, без изменения протокола opaque Bearer sessions.

В коллекции нет admin grant endpoint, публикации события и браузерной админки. Управление модерацией описано в [MODERATION](../../backend/MODERATION.md). Отправка формы пользователя сама по себе не публикует событие и не подтверждает корректность предложенного источника.
