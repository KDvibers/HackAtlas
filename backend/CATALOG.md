# Каталог B1

Источник API — [Starter OpenAPI](../api/openapi.yaml) и [семантика](../api/README.md). Этот документ описывает серверные решения внутри контракта. Каталог публичный; аккаунты и opaque Bearer sessions относятся к B2.

## Операции

| Метод и путь | Результат |
|---|---|
| `GET /api/v1/hackathons` | Страница карточек; фильтры, поиск и сортировка |
| `GET /api/v1/hackathons/{id}` | Полные сведения опубликованного события |
| `GET /api/v1/metadata/filters` | Доступные фильтры и допустимые интересы |

Список включает опубликованные неархивные события, кроме завершённых и отменённых. Опубликованные завершённые и отменённые события доступны по ID. Draft/archived и отсутствующий UUID дают одинаковый 404.

Поиск `query` работает без учёта регистра по названию, организатору, названиям тем и городу. Пробелы по краям убираются; пустой поиск не ограничивает выдачу. `%`, `_` и SQL-подобный текст остаются текстом поиска. Все переданные фильтры соединяются AND.

`countryCode` и `city` относятся к месту проведения. `individualApplicationAllowed=true` включает только явно разрешённую индивидуальную заявку. `startsFrom`/`startsTo` сравнивают начальную локальную дату включительно; событие без даты не попадает под заданный диапазон.

Сортировки:

- `DEADLINE_ASC` — по умолчанию, дата дедлайна, затем известное время.
- `START_ASC` — дата начала, затем известное время.
- `NEWEST` — серверный `publishedAt DESC`.

Для одной даты неизвестное время идёт после известного; неизвестная дата — после известных. При равенстве применяется `id ASC`. Временная зона не превращает календарную сортировку в глобальную хронологию.

`page` начинается с 0, `size` по умолчанию 20, диапазон 1–50. Очень большой допустимый номер страницы возвращает пустой `items`, сохраняя настоящий `totalElements`/`totalPages`. `totalPages=0` означает отсутствие результатов вообще, а не только пустую запрошенную страницу.

## Время и статусы

Одна операция использует один момент из внедрённого `Clock`; `asOf` списка соответствует этому моменту. `EventTime` сохраняет DATE/MINUTE, локальную дату, nullable время/зону и согласованный instant. Для DATE не создаются искусственные 00:00 или 23:59.

Организаторские `CANCELLED`, `POSTPONED`, `ENDED` имеют приоритет над датами. Для обычного события:

- MINUTE начало наступает при `instant <= now`; окончание — при `instant <= now`.
- DATE начало считается наступившим в указанную локальную дату; окончание — только после завершения всей локальной даты.
- DATE без известной зоны не вызывает автоматического перехода по времени.

Отменённое или завершённое событие имеет закрытую регистрацию. Явный `CLOSED` сохраняется. Известный прошедший дедлайн закрывает регистрацию: MINUTE — по instant, DATE — только после локальной даты при известной зоне. Для `POSTPONED` старый дедлайн не используется. Оставшиеся OPEN/UPCOMING/UNKNOWN сохраняют сведения организатора; сервер не открывает регистрацию только из-за будущего дедлайна.

Эти состояния описывают мероприятие и набор организатором. Они не подтверждают право конкретного человека участвовать или факт подачи заявки.

## Metadata и неизвестные значения

Topics/formats/countries/cities строятся по событиям, доступным в текущем публичном каталоге. Поэтому fixture metadata с HYBRID является примером формы ответа: при отсутствии доступных HYBRID-событий этот формат не добавляется искусственно. Interests берутся из разрешённых справочных тегов, включая навыки.

Неизвестные nullable поля присутствуют в JSON с `null`. `allowedCountryCodes=null` означает неизвестные условия, а `[]` — отсутствие географических ограничений. Денежная сумма передаётся десятичной строкой из `BigDecimal`; неизвестный приз не превращается в нулевой.

## Ошибки

Невалидные параметры, UUID, диапазон дат, повтор одиночного параметра, неизвестное имя или некорректная строка параметров дают 400 `VALIDATION_ERROR`. Значения фильтров, которых нет среди событий, дают пустую страницу, если сами значения соответствуют контракту.

Ошибки содержат все поля Starter `Problem`, имеют `Content-Type: application/problem+json` и серверный `requestId`, совпадающий с `X-Request-Id`. Клиентский request ID не принимается как доверенный. В ответы не попадают SQL, исключения, параметры подключения или stack trace.

## DEMO для локальной разработки

Обычный запуск не загружает события. Для явного DEMO после запуска PostgreSQL и успешной сборки, из `backend/`:

```text
java -jar target/hackatlas-backend-0.1.0-SNAPSHOT.jar --spring.profiles.active=dev --hackatlas.demo.enabled=true
```

Для воспроизводимого просмотра исходных fixtures на их дату можно дополнительно передать:

```text
--hackatlas.demo.as-of=2026-10-12T10:00:00Z
```

Фиксированный clock допускается только вместе с DEMO в dev/test. При обычном запуске используется текущее UTC-время. Старая DEMO-подборка со временем может исчезнуть из списка из-за истечения дат; не менять реальные даты ради демонстрации.

Seed читает общий комплект `api/examples`, сохраняет UUID и исходные поля, не создаёт аккаунты. Для остальных четырёх событий, кроме подробного AI fixture, дополнительные поля деталей явно демонстрационные/неизвестные. Повтор seed идемпотентен. Миграции production не содержат DEMO; явный профиль `prod` запрещает загрузку даже при совместном указании dev/test.

Пример запроса из PowerShell:

```powershell
Invoke-RestMethod 'http://127.0.0.1:8080/api/v1/hackathons?format=ONLINE&size=2'
Invoke-RestMethod 'http://127.0.0.1:8080/api/v1/hackathons/39287368-5259-5235-a1c4-25b4e1e8421e'
Invoke-RestMethod 'http://127.0.0.1:8080/api/v1/metadata/filters'
```

Адрес относится к компьютеру с сервером. Для Android emulator и устройств нужен отдельный доступный host mapping/LAN; `localhost` телефона не указывает на этот компьютер. HTTPS staging и изменение firewall/внешнего bind не выполняются автоматически. `example.com` в DEMO не является настоящей регистрацией.
