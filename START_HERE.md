# С чего начать вам двоим

## Это уже сделано в комплекте
Два подробных Codex-промпта, общие AGENTS.md, правила стиля, утверждённое фото, API-контракт с fixtures, этапы и GitHub-процесс. Основа backend B0 и публичный каталог B1 объединены в main. На мобильной стороне реализованы M0/M1 и локальная часть M2; визуал M1 утверждён, Android проверен, iOS требует Mac/Xcode. Авторизация B2 и интеграция REMOTE-каталога остаются отдельными этапами. Старые HTML/Figma-файлы не использовать как основной эталон вместо фото.

## 1. Существующий общий GitHub-репозиторий
Репозиторий уже создан: [KDvibers/HackAtlas](https://github.com/KDvibers/HackAtlas). Его первоначальная история сохранена. Повторный `git fetch origin` 20 октября подтвердил merge B0 в `origin/main` (`43b11e4`, PR #2); B0 commit — `208e097`. B1 также объединён в main через PR #3 (`959e2f4`). Мобильная ветка `feat/mobile-bootstrap` представлена в PR #4. Commit, push и новые PR выполняет пользователь.

В существующем клоне не повторять `git init` и не распаковывать ZIP поверх изменений. Для новой машины:

```bash
git clone https://github.com/KDvibers/HackAtlas.git
cd HackAtlas
git status --short --branch
```

У каждого разработчика свой аккаунт и локальный клон. Для серверной работы используется GitHub-аккаунт `yergaliuly`. GitHub handle напарника пока не указан; не подставлять случайный аккаунт в CODEOWNERS.

Единственный актуальный комплект — Starter. Правила авторизации: opaque Bearer sessions по `api/`, без JWT и refresh endpoint. См. [решения](docs/DECISIONS.md) и [результат аудита](docs/SETUP_AUDIT.md).

Перед новым этапом оба разработчика читают [PROJECT](docs/PROJECT.md), [TECHNOLOGY_DECISIONS](docs/TECHNOLOGY_DECISIONS.md), [общий ROADMAP](docs/ROADMAP.md) и статус своей части. Исследование сохраняет варианты; принятые технологии и условия выбора зафиксированы отдельно. Проверяйте ветку, из которой друг получил документы и код: доступность feature-ветки не означает её включение в main.

## 2. Твой Codex
Открой локальный корень HackAtlas, прочитай `docs/STATUS_BACKEND.md` и `prompts/BACKEND_CODEX.md`. Промпт описывает B0+B1, но границу работы задаёт текущий запрос пользователя. B1 находится в main; [запуск и проверки](backend/README.md) доступны в репозитории. Следующий отдельный этап — B2, без автоматического перехода. При повторном входе опирайся на статус и существующий код.

## 3. Codex друга
Мобильный разработчик открывает свой clone того же репозитория и читает `docs/STATUS_MOBILE.md`, `mobile/README.md` и стартовый промпт как контекст. M0/M1 и локальная часть M2 уже реализованы, визуал утверждён. Повторно начинать bootstrap не нужно. Следующий отдельно согласованный шаг — REMOTE-каталог; утверждённые экраны, шрифты и API сохраняются.

## 4. Что можно делать параллельно
Backend-разработчик передаёт проверенные команды запуска B1 и доступный мобильному устройству base URL. Мобильный разработчик после согласования подключает REMOTE repository, сохраняя UI, гостевые закладки и календарь. Оба используют неизменённый Starter API.

Авторизация и синхронизация требуют готового B2 и отдельного поручения. Успешный локальный запуск сервера не означает доступность его адреса с другого компьютера или телефона.

## 6. Важные ограничения
iOS build/device verification требуют подходящего Mac+Xcode; kit не создаёт к ним доступ. Нет Mac — Android/common можно делать, но iOS остаётся непроверенным до реального запуска. Публикация новых изменений остаётся за пользователем. В исходном Starter шрифтов не было; выбранные для M1 шрифты, источники и лицензии описаны в `design/assets/REGISTRY.md`. Точный исходный шрифт фото не установлен. API — исходный договор, не доказательство готового endpoint.
