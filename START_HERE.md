# С чего начать вам двоим

## Это уже сделано в комплекте
Два подробных Codex-промпта, общие AGENTS.md, правила стиля, утверждённое фото, API-контракт с fixtures, этапы и GitHub-процесс. Приложение и сервер ещё предстоит реализовать. Старые HTML/Figma-файлы не использовать как основной эталон вместо фото.

## 1. Один общий GitHub-репозиторий
Создайте **пустой** репозиторий HackAtlas в выбранной organization либо аккаунте. Не добавляйте GitHub README/gitignore/license на этом шаге, чтобы не создавать две начальные истории. Пригласите второго участника. Регистрироваться под одним логином не нужно.

Распакуйте содержимое этого комплекта в локальную папку будущего проекта (не в уже существующий рабочий репозиторий без проверки). Ниже `YOUR_REMOTE_URL` заменить точным URL, скопированным из GitHub; это единственный обязательный placeholder в командах.

```bash
git init -b main
git status --short
git add .
git diff --cached --stat
git commit -m "chore: add HackAtlas specification and Codex briefs"
git remote add origin YOUR_REMOTE_URL
git push -u origin main
```

Перед первым commit проверьте, что в папку не попали чужие файлы/секреты. Это одноразовый bootstrap. Дальше feature branches и PR. Если GitHub repo уже существует с историей, сначала clone/pull и перенос спецификаций после сравнения; не повторять init и не force push.

Друг клонирует **этот же** remote. На каждой машине свой рабочий каталог. Файлы комплекта не надо раз за разом перезаписывать после начала разработки.

## 2. Твой Codex
Открой локальный корень HackAtlas, вставь **полный текст** `prompts/BACKEND_CODEX.md`. Он запускает B0+B1: Java-сервис и настоящий API каталога. При повторном входе не сбрасывай контекст проекта, опирайся на STATUS_BACKEND.

## 3. Codex друга
Друг открывает свой clone того же репозитория, прикрепляет утверждённое фото и вставляет **полный текст** `prompts/MOBILE_CODEX.md`. Он запускает M0+M1: cross-platform каркас и три главных экрана на общих fixtures. После проверки внешнего вида остановиться на утверждение, а не автоматически делать остальные экраны в неправильном стиле.

## 4. Что можно делать параллельно
Ты делаешь API каталога, друг — визуальное ядро на fixtures. Обоим доступны один API и одна картинка. Твоя готовность B1 не зависит от завершения его дизайна; его M1 не зависит от запущенного сервера.

После B1 отправь другу сообщение из отчёта Codex, сделай PR и merge с проверками. Друг обновляет main и подключает remote repository, сохранив UI. Переход к auth только после согласованного этапа.

## 5. Короткий запрос на продолжение
Тебе:
> Прочитай AGENTS.md, docs/STATUS_BACKEND.md, API и текущее состояние git. Продолжи со следующего согласованного backend этапа, не трогай mobile и стиль. Не переделывай выполненное. Сначала покажи фактический статус, затем выполни один этап и проверь его.

Другу:
> Прочитай AGENTS.md, mobile/AGENTS.md, STYLE_LOCK и STATUS_MOBILE. Визуально сверяйся с approved-reference.png. Продолжи только следующий согласованный этап без редизайна. Сначала установи, утверждены ли M1 screenshots; до утверждения не переходи к M2. В конце реальные проверки и screenshots.

## 6. Важные ограничения
iOS build/device verification требуют подходящего Mac+Xcode; kit не создаёт к ним доступ. Нет Mac — Android/common можно делать, но iOS остаётся непроверенным до реального запуска. GitHub publication не выполнена этим комплектом. Файлы шрифтов не приложены, точный шрифт фото не установлен. API — исходный договор, не доказательство готового endpoint.
