# С чего начать вам двоим

## Это уже сделано в комплекте
Два подробных Codex-промпта, общие AGENTS.md, правила стиля, утверждённое фото, API-контракт с fixtures, этапы и GitHub-процесс. Backend B0–B2 объединён в main; B3 подготовлен локально в `feat/backend-moderation`. На мобильной стороне реализованы M0/M1 и локальная часть M2; визуал M1 утверждён, Android проверен, iOS требует Mac/Xcode. Интеграция REMOTE-каталога остаётся отдельным мобильным этапом. Старые HTML/Figma-файлы не использовать как основной эталон вместо фото.

## 1. Существующий общий GitHub-репозиторий
Репозиторий уже создан: [KDvibers/HackAtlas](https://github.com/KDvibers/HackAtlas). Его первоначальная история сохранена. На начало B3 объединены B0 PR #2, B1 PR #3, mobile PR #4 и B2 PR #5; база B3 — `20464e7`. За время B3 напарник объединил HTTP-client PR #6, свежий `origin/main` — `04407db`. Он не меняет backend/API и файлы B3; локальная ветка остаётся на исходной базе, merge не выполнялся. Commit, push и новые PR выполняет пользователь.

В существующем клоне не повторять `git init` и не распаковывать ZIP поверх изменений. Для новой машины:

```bash
git clone https://github.com/KDvibers/HackAtlas.git
cd HackAtlas
git status --short --branch
```

У каждого разработчика свой аккаунт и локальный клон. Для серверной работы используется GitHub-аккаунт `yergaliuly`. GitHub handle напарника пока не указан; не подставлять случайный аккаунт в CODEOWNERS.

Единственный актуальный комплект — Starter. Правила авторизации: opaque Bearer sessions по `api/`, без JWT и refresh endpoint. См. [решения](docs/DECISIONS.md) и [результат аудита](docs/SETUP_AUDIT.md).

Перед новым этапом оба разработчика читают [PROJECT](docs/PROJECT.md), [TECHNOLOGY_DECISIONS](docs/TECHNOLOGY_DECISIONS.md), [общий ROADMAP](docs/ROADMAP.md) и статус своей части. Исследование сохраняет варианты; принятые технологии и условия выбора зафиксированы отдельно. Проверяйте ветку, из которой друг получил документы и код: доступность feature-ветки не означает её включение в main.

## 2. Твой Codex
Открой локальный корень HackAtlas, прочитай `docs/STATUS_BACKEND.md` и `prompts/BACKEND_CODEX.md`. Промпт описывает B0+B1, но границу работы задаёт текущий запрос пользователя. B0–B2 находятся в main; B3 подготовлен в `feat/backend-moderation`. [Запуск и проверки](backend/README.md) доступны в репозитории. Следующий отдельный этап — B4, без автоматического перехода. При повторном входе опирайся на статус и существующий код.

## 3. Codex друга
Мобильный разработчик открывает свой clone актуальной main и читает `docs/STATUS_MOBILE.md`, `mobile/README.md` и стартовый промпт как контекст. M0/M1, локальная часть M2 и HTTP-слой из PR #6 уже реализованы, визуал утверждён. Повторно начинать bootstrap не нужно. Следующий отдельно согласованный шаг — живое подключение REMOTE-каталога; утверждённые экраны, шрифты и API сохраняются.

## 4. Что можно делать параллельно
Backend-разработчик передаёт [инструкцию запуска B1 из main](docs/B1_MOBILE_HANDOFF.md): общего сервера пока нет, для интеграции рекомендуется запуск на компьютере напарника. Мобильный разработчик после согласования подключает REMOTE repository, сохраняя UI, гостевые закладки и календарь. Оба используют неизменённый Starter API.

Авторизация и синхронизация клиента подключаются по отдельному поручению после передачи B2; серверные правила описаны в [AUTH](backend/AUTH.md). Успешный локальный запуск сервера не означает доступность его адреса с другого компьютера или телефона.

## 6. Важные ограничения
iOS build/device verification требуют подходящего Mac+Xcode; kit не создаёт к ним доступ. Нет Mac — Android/common можно делать, но iOS остаётся непроверенным до реального запуска. Публикация новых изменений остаётся за пользователем. В исходном Starter шрифтов не было; выбранные для M1 шрифты, источники и лицензии описаны в `design/assets/REGISTRY.md`. Точный исходный шрифт фото не установлен. API — исходный договор, не доказательство готового endpoint.
