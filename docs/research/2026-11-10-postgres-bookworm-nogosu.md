# PostgreSQL Bookworm без gosu — локальная проверка

10 ноября 2026. Проверен кандидат Linux amd64 на `main` `19ad561`.
[PR #44](https://github.com/KDvibers/HackAtlas/pull/44) содержит исходный разбор
четырёх `CRITICAL`. Цель этого прогона — проверить, нужна ли утилита `gosu` при
штатном запуске HackAtlas от UID `999`, и измерить эффект её удаления в Trivy.

## Кандидат

Из текущего закреплённого образа собрана локальная производная. PostgreSQL и
операционные клиенты берутся из того же образа.

```dockerfile
FROM postgres:17.11-bookworm@sha256:839fbb5a4942a7758dd93e18b42ea5649807491a0545b5eeeb8f0b8bb11857a5
RUN rm /usr/local/bin/gosu
USER 999:999
```

Локальный тег — `postgres:17.11-bookworm-nogosu-probe-20261110`. Сборка
выполнялась с `--network none`. Проверены UID/GID `999:999`, отсутствие
`/usr/local/bin/gosu`, одинаковые версии всех 144 Debian-пакетов и контрольные
суммы `postgres`, `pg_dump`, `pg_restore` и `docker-entrypoint.sh`.

Официальный entrypoint вызывает `gosu` при запуске самого PostgreSQL от root.
Релизный процесс работает от `999:999`, а подготовка томов запускает `/bin/sh`
как отдельный root-процесс. Проверка кандидата охватывает именно эту схему.
Удаление относится к итоговой файловой системе образа. Нижний слой исходного
образа остаётся частью производного OCI-архива.

## Trivy и независимый инвентарь

| PostgreSQL 17.11 Bookworm | CRITICAL | HIGH | MEDIUM | LOW | UNKNOWN |
| --- | ---: | ---: | ---: | ---: | ---: |
| Закреплённая база с `gosu` | 4 | 117 | 210 | 174 | 26 |
| Кандидат без `gosu` | 3 | 92 | 179 | 171 | 25 |

Сравнение выполнено на одной свежей базе Trivy. Запись
[`CVE-2025-68121`](https://pkg.go.dev/vuln/GO-2026-4337) из Go stdlib исчезла.
Остались `CVE-2025-7458` (`libsqlite3-0`), `CVE-2026-6653` (`libxml2`) и
`CVE-2023-45853` (`zlib1g`). Находки по Debian совпали до и после. Разница
целиком относится к `usr/local/bin/gosu`. Счётчики отражают пары «пакет — advisory».

Отдельная проверка экспортировала итоговые файловые системы двух созданных,
но не запущенных контейнеров. В базе найден один ELF с Go build info среди
939 ELF-файлов, `/usr/local/bin/gosu`. У кандидата среди 938 ELF-файлов таких
признаков не найдено. Проверка использовала маркеры из
[Go debug/buildinfo](https://go.dev/src/debug/buildinfo/buildinfo.go) и имени
секции `.note.go.buildid`. Сами экспорты не входят в PR.

## Восстановление Bookworm → Bookworm без gosu

На двух отдельных кластерах от UID `999` `pg_dump -Fc` из исходного образа
восстановился через `pg_restore --exit-on-error --single-transaction` в
кандидат. Совпали четыре строки с Unicode и JSONB, три индекса валидны.
Кодировка `UTF8`, локаль `en_US.utf8` и версия collation `2.36` совпали.

## Сборка и штатная репетиция

- В отдельной копии `main` три ссылки Testcontainers временно направлены на
  собранный тег. В логах подтверждён запуск именно этого образа. Maven `verify`
  собрал JAR и выполнил **47 unit + 311 integration** без ошибок и пропусков.
- Во второй временной копии `main` кандидат указан для `postgres` и
  `init-volumes`. `run_rehearsal.py` собрал приложение и Caddy и выполнил
  **12 проверок за 151,464 с**. Проверены повторная подготовка томов, права
  runtime, HTTPS с проверкой сертификата, backup, карантин, учёт удалений и
  миграции V6–V9. Использован ранее проверенный JAR `a890e4b…` из того же Java source.
- Прошли 28 тестов аудита, валидатор канонического OpenAPI и 13 примеров.

## Что показал общий аудит

Штатный `run_container_audit.py` просканировал все три образа из репетиции и
записал их отчёты. Проверены SHA-256 отчётов, совпадение image ID с контейнером
репетиции и свежая общая база уязвимостей. Для PostgreSQL полный прогон повторил
результат сравнения. Единственный тип инвентаря кандидата — `debian`.

Текущая политика требует `gobinary` для любого PostgreSQL. Поэтому после
успешного сканирования она завершилась кодом `2` с `postgres language inventory
missing` и `evidenceComplete=false`. Отдельно у кандидата остаются три
`CRITICAL` по Debian. Наличие сырых отчётов и снятие одной CVE не открывают выпуск.

Следующий отдельный шаг для включения кандидата — закрепить происхождение
производного образа и правило, которое сверяет фактическое отсутствие Go ELF
с точным ID испытанного образа. Для обычного PostgreSQL с Go-бинарником текущая
проверка Go-инвентаря должна оставаться обязательной. Пропавший отчёт, пустой
инвентарь без доказательства и несовпадение image ID должны блокировать допуск.
В текущий PR входят отчёт и статус локального эксперимента.

Артефакты находятся в ignored `backend/target/`: `b4-pg-nogosu-image.json`,
`b4-pg-nogosu-audit/`, `b4-pg-nogosu-rehearsal/`, `b4-pg-nogosu-full-audit/`
и `b4-pg-nogosu-maven.log`.
