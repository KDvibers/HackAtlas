# M3: личная отметка подачи заявки

Статус: утверждён пользователем 5 ноября 2026 — сервер + просмотр кеша без очереди.
Дата: 5 ноября 2026. Ветка `feat/mobile-application-marks`, base `c1c3718` (PR27 merged).

## Цель и уже согласованные границы

Пользователь разрешил следующий отдельный блок M3: вручную поставить/снять
«Я подал(а) заявку», сохранить через сервер и восстановить после перезапуска.
Это личная заметка пользователя, не отправка формы и не подтверждение организатора.
Переход к регистрации и «Поделиться» не создают отметку. Закладка независима.
Напоминания, verification/reset, смена API, новые вкладки и новый дизайн не входят.
Стек KMP/Compose/Ktor/opaque sessions прежний, новых библиотек не требуется.
Commit/push/PR выполняет пользователь.

## Подходы

1. **Рекомендуемый:** сервер подтверждает изменения, приватный кеш используется
   для просмотра без сети. Поведение соответствует уже выбранному режиму saved.
   Меньше состояний и риска применить отложенное действие другому пользователю.
2. Очередь offline-изменений с последующей отправкой. Позволяет нажать кнопку
   без сети, но добавляет неподтверждённые отметки, восстановление очереди,
   повторы/смену владельца и отдельные правила конфликтов. Для этого блока избыточна.

Пользователь отдельно утвердил первый вариант и весь этот короткий дизайн.

## Предлагаемое поведение

- Контрол в подробностях события рядом с пояснением о внешней регистрации,
  в существующем тёмном/магентовом стиле; основная кнопка регистрации остаётся.
- Гостю доступен вход. Только REMOTE-аккаунт пишет в защищённые endpoints;
  bundled DEMO не имитирует серверный успех. REMOTE DEMO-события сохраняют пометку DEMO.
- До получения полного списка состояние неизвестно: незагруженные страницы
  нельзя трактовать как отсутствие отметки. Показать загрузку/повтор, без ложного «не подано».
- PUT с валидным ответом показывает отметку, исходный markedAt и пояснение
  «Отмечено вами». DELETE с204 снимает её. Во время запроса повторное действие
  заблокировано; ошибка не превращается в успех. После потерянного ответа —
  явное обновление/повтор идемпотентной операции, без скрытого optimistic success.
- При offline только чтение ранее подтверждённого кеша, с датой копии и
  предупреждением о возможном устаревании; очередь/локальная запись действия отсутствует.
- Счётчик заявок профиля обновляется серверным GET /me; локально его не выдумывать.
  Отдельного списка заявок/нового экрана в этом небольшом блоке нет.

## Контракт и интеграция

Единственный источник — существующие api/openapi.yaml + api/README.md:
GET /me/applications(page,size) -> ApplicationPage;
PUT /me/applications/{id} -> ApplicationMark;
DELETE /me/applications/{id} ->204.
APPLIED/selfReported=true обязательны; проверяются hackathonId/markedAt и
пагинация. Повторный PUT не меняет markedAt. Текущие канонические guards не расширяются.

Методы клиента используют существующий AuthSessionClient, owned-session mutex
и expectedUserId. Токен не выходит в UI/cache. 401 использует прежний путь
завершения сессии; raw server payload в UI не выводится.

Отдельный store ведёт source+user owner, поколение запросов, загрузку всех страниц,
ожидающую мутацию и ошибки. Старые ответы после logout/account switch/source switch
не меняют UI или диск. Приватный кеш отметок хранится отдельно от saved cache и
старых гостевых файлов. Очистка после logout/смены владельца обязательна; сбой
очистки блокирует приватное состояние до повтора. Схемы существующих файлов не менять.
Host Android/iOS подключаются к общей логике; отдельные платформенные экраны не нужны.

## Проверка и результат блока

MockEngine: GET/PUT/DELETE, Bearer только своему API, валидные/невалидные ответы,
повторный markedAt, ошибки/401, pagination и отмена. Store/cache tests: неизвестное
состояние до полной загрузки, offline cache/restart, ошибка мутации без ложного
успеха, дубликаты/гонки, смена аккаунта, очистка и независимость от bookmarks/браузера.
Полный shared suite, Android debug/lint/release gate и contract validation.
Android приёмка/скриншоты на доступном устройстве, включая крупный текст; реальную
HTTP-проверку отличать от fixtures. Native iOS требует Mac и не заявляется на Windows.
В конце один независимый read-only review, статус, PR body и команды commit/push.
