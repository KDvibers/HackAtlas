# Принятые решения

## 12 октября 2026 — единая спецификация

По прямому указанию пользователя единственный актуальный комплект — `HackAtlas_Codex_Starter (1).zip`. Handoff исключён из источников реализации. Совпадение номера API `0.1.0` между комплектами не означает совместимость: актуальны схемы и семантика только из `api/openapi.yaml` и `api/README.md` Starter.

Авторизация — серверные opaque Bearer sessions. Случайный токен не менее 256 bits entropy; в БД хранится его hash, срок и состояние отзыва. JWT, refresh endpoint и refresh-token flow отсутствуют. AuthResponse содержит `tokenType`, `accessToken`, `expiresAt`, `user`; имя `accessToken` не меняет opaque-природу токена. Реализация относится к B2. Существующую авторизацию нельзя заменять без отдельного согласования.

Публичные маршруты B1: `/api/v1/hackathons`, `/api/v1/hackathons/{id}`, `/api/v1/metadata/filters`. Приватное сохранённое — `/me/saved`, ошибки используют `requestId`. Полные схемы остаются в OpenAPI; этот файл не заменяет контракт.

## Историческая граница G0 — 12 октября 2026

Запрошенный «этап 1» соответствует G0 из ROADMAP: аудит репозитория и окружения, перенос Starter, фиксация решений, проверка контракта и передача результата. B0/B1 из вложенного промпта не запускаются автоматически. Следующее отдельное задание — B0.

Пользователь подтвердил Starter как единственный актуальный комплект. Получение этой же версии напарником и его review общего API ещё не проверены; это часть пользовательского PR, а не уже выполненное действие.

## 20 октября 2026 — направление и общий план закреплены

После исследования пользователь поручил закрепить выбранную идею и составить общий план с технологиями для двух разработчиков. G0 уже находится в `origin/main` (`0128f7b`, merge PR #1). Сам факт merge не подтверждает отдельную проверку контракта напарником.

Продуктовый фокус: проверяемый каталог для Казахстана и подходящих международных online-событий. Пять ориентиров реализации: видимый источник и свежесть проверки; раздельные дедлайн заявки и начало события; быстрые фильтры; сохранённое без сети; добровольная личная отметка заявки после перехода на сайт организатора. Полное описание и границы — в [PROJECT](PROJECT.md).

Подтверждена прежняя основа Java 21 / Spring Boot 4.x / PostgreSQL 17 и KMP / Compose. В [TECHNOLOGY_DECISIONS](TECHNOLOGY_DECISIONS.md) зафиксированы выбранные технологии, инструменты по этапам и кандидаты с условиями принятия. В [ROADMAP](ROADMAP.md) — единый план владельца backend и мобильного напарника с зависимостями и критериями готовности.

Это решение не утверждает все альтернативы из исследования. Navigation, полноценная offline DB и конкретный display font ещё требуют указанных проверок; номера версий из research не являются lockfile. Смена стека, auth, API и визуального направления остаётся предметом отдельного согласования. Рутинная реализация в выбранных границах и совместимые исправления не требуют нового разрешения на каждый файл.

Список продуктовых гипотез сохранён в [исследовании](research/2026-10-20-technology-research.md); он не расширяет текущий MVP автоматически. Канонический контракт, fixtures и референс не изменены.

Границей того задания была фиксация документов и общего плана без реализации приложения. На его завершении следующим отдельным этапом backend был B0; мобильной стартовой работой — M0/M1.

## 20 октября 2026 — отдельно поручен B0

Пользователь разрешил создать основу backend, проверить сборку и тесты, затем остановиться: «К B1 пока не переходи, пуш и PR делаю я». Работа выполняется в `feat/backend-bootstrap` поверх локального дополнения с планом `6e6071c`; она не включает реализацию каталога, opaque sessions или mobile.

Выбран совместимый набор Java 21 / Spring Boot 4.1.1 BOM / Maven 3.9.16 / PostgreSQL 17.11 с закреплённым image digest. Воспроизводимые команды, точные версии и минимальная Windows-правка официального Wrapper описаны в [backend/TOOLCHAIN](../backend/TOOLCHAIN.md). Spring Security подключается на B2 по принятому протоколу opaque Bearer; существующей реализации auth на старте B0 не было.

Схемой управляет Flyway: первая миграция создаёт только namespace `hackatlas`, history остаётся в `public`; Hibernate использует `validate`. Тесты работают на отдельном PostgreSQL Testcontainers, dev использует отдельный Compose project, prod не импортирует dev `.env`. Health раскрывает статус и имена публичных probes, без компонентов, строк подключения и внутренних деталей.

Старое указание `backend/AGENTS.md` выполнить B0+B1 в первой сессии приведено к корневому правилу: границу определяет актуальное поручение. Старый стартовый промпт остаётся справочным и не разрешает B1. Контракт Starter, fixtures, mobile и визуальный референс не менялись. Фактический отчёт — [STATUS_BACKEND](STATUS_BACKEND.md).
