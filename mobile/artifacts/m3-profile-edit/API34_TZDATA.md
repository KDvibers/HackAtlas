# Каталог на старом образе с tzdata2023a

Обнаружено 3 ноября 2026 во время Android-приёмки PR24. Это отдельный открытый
вопрос совместимости существующей проверки каталога, не изменение профиля/API.

## Воспроизведение и причина

Установленный Google Play образ Android14/API34 содержит tzdata2023a.
Для DEMO AI Sprint сервер возвращает согласованную пару:

- 2026-11-12,10:00,Asia/Almaty;
- instant2026-11-12T05:00:00Z.

На этом образе системный date переводит тот же instant в
2026-11-12T11:00:00+0600. Общий ContractMapping сверяет local time с instant через
правила ОС и отклоняет страницу как InvalidResponse. Это воспроизведено до входа.

[IANA tzdb2024a](https://data.iana.org/time-zones/tzdb/NEWS) содержит переход
Asia/Almaty на UTC+5 с1марта2024. На API36/tzdata2025a проверено преобразование
2026-11-12T10:00:00+0500; весь профильный прогон6/6 проходит.

## Границы результата

Результат API34 относится к конкретному образу с2023a. Образы/устройства API34
с обновлёнными правилами в этом запуске не проверялись. Минимальный SDK приложения26
сам по себе не гарантирует актуальность системной tzdata.

Для поддержки старых правил нужна отдельная согласованная задача по политике
проверки MINUTE. В PR24 не подменялись даты/fixtures, не ослаблялась валидация,
не менялись backend/OpenAPI и не добавлялись библиотеки. Успех6/6 на API36 не
закрывает этот отдельный вопрос совместимости.
