# Mobile ownership

Прочитать корневой `AGENTS.md`. Ты отвечаешь за `mobile/`, ресурсы `design/assets/`, `docs/STATUS_MOBILE.md` и будущий `.github/workflows/mobile-ci.yml`.

Общие экраны и логика — Kotlin, Compose Multiplatform, commonMain. Swift — только минимальная оболочка/интеграция iOS, не второй комплект экранов. Предпочтительная структура: `mobile/shared`, `mobile/androidApp`, `mobile/iosApp`, один собственный Gradle wrapper внутри `mobile/`.

Не менять `backend/`, `infra/`, API и корневые правила самостоятельно. Недостающие API оформлять как запрос напарнику.

Визуальные правила: `docs/STYLE_LOCK.md`. По умолчанию тёмная тема; насыщенная фуксия, немного cyan, пиксельные заголовки, сетчатые иллюстрации. Не использовать dynamic color, стандартный вид Material 3, emoji вместо иконок и неоновую заливку всего экрана.

Сначала M0 + M1, не весь roadmap. До визуального подтверждения каталога, подробностей и профиля не размножать дизайн на остальные экраны. При отсутствии возможности сделать screenshot честно указать, что визуальная приёмка не проведена, и дать шаги проверки на устройстве.

DEMO/REMOTE выбираются явно. Сетевую ошибку нельзя маскировать переключением на mock-данные. Release не должен содержать включённый demo-режим или dev-http.
