# HackAtlas: обязательные правила для Codex

## Сначала прочитать
- `docs/PROJECT.md`, `docs/ROADMAP.md`, `docs/WORKFLOW.md`.
- `api/README.md`, `api/openapi.yaml`, `api/examples/`.
- Для мобильной работы: `mobile/AGENTS.md`, `docs/STYLE_LOCK.md` и визуально `design/reference/approved-reference.png`.
- Для сервера: `backend/AGENTS.md`.

## Границы
- Клиент: Kotlin Multiplatform + Compose Multiplatform, Android и iOS. Сервер: Java 21 + Spring Boot. Не менять стек без согласования.
- Главный визуальный источник — приложенное изображение. Не «осовременивать», не делать минималистичный Material-шаблон, не менять пиксельные заголовки на обычные.
- Скриншот — референс, не допустимая реализация UI. Кнопки, текст, карточки должны быть настоящими компонентами.
- В MVP нет поиска команды, чата, оплаты, собственной подачи заявки организатору, AI-рекомендаций или сборщика «всех хакатонов мира».
- Канонический API: `api/openapi.yaml` вместе с семантикой `api/README.md`. Изменять по отдельному согласованному PR с обеими сторонами, не подгонять односторонне.
- Непроверенные события и моковые профили — DEMO. Не переносить вымышленные призы, победы и регистрации в реальные данные.

## Рабочий процесс
- В начале проверить `git status`, текущую ветку, структуру, доступные SDK и существующий код. Не переписывать рабочий проект и не удалять чужие изменения.
- Код можно создавать и редактировать в пределах задания. Не выполнять push, merge, публикацию, удаление данных или платный deployment без отдельного разрешения пользователя.
- Не использовать `git reset --hard`, `git clean -fd`, force push и тихое скрытие чужих изменений в stash.
- Один этап → небольшой проверяемый результат → тесты → отчёт. После согласованной границы этапа остановиться.
- Не отключать тесты, линтеры, проверки сертификатов и безопасности ради зелёной сборки.
- Секреты, реальные `.env`, ключи подписи и signing profiles не коммитить. Никаких font binaries в этом передаваемом комплекте; шрифты выбирать отдельно с источником и лицензией.
- Не утверждать, что iOS собран, эмулятор запущен или тесты пройдены, если это не выполнялось.

## Отчёт в конце этапа
Что изменено; точные пути; выполненные команды и результат; что не удалось проверить; скриншоты при UI-работе; изменения API; короткое сообщение напарнику; следующий отдельный этап. Обновить только свой `docs/STATUS_BACKEND.md` или `docs/STATUS_MOBILE.md`.
